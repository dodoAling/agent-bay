# Implementation review

Updated 2026-10-17. This document separates completed fixes, verified behavior, and remaining work.

## Implemented behavior

1. **Lifetime counters surviving retention.** Sessions independently accumulate calls, successes, errors, pending work, checks, tokens, and total events. The 5000-event limit applies only to details. Duplicate IDs, token accounting, refresh, SSE reconnect, session switching, Canvas summaries, and demo isolation are covered. Removed inputs/results are explicitly unavailable.
2. **Incomplete model responses failing correctly.** Chat Completions and Messages validate termination reasons consistently for JSON and SSE. Token limits, errors, filtering, and missing/unknown reasons fail explicitly. Truncated tool arguments are never executed. Nonstandard providers must report a supported termination reason; automatic `pause_turn` continuation is not implemented.
3. **Proxy telemetry recovery.** A FIFO queue retries with exponential backoff and stable event IDs. The server acknowledges/deduplicates by source, run, and ID. Actual MCP subprocess, HTTP event delivery, lost acknowledgements, and queue overflow tests confirm that retries do not re-execute tools or alter MCP stdout.
4. **Readable work layouts and results.** A responsive five-node live pipeline provides readable text and larger results. REA views show actual counts, provenance, and coverage, with collapsible structured details, raw JSON, and arguments. Markdown, highlighting, and copying work. Model deltas preserve selected tool details; updates preserve reading position.
5. **Distinct lifecycle states.** Working, waiting, completed, failed, cancelled, and disconnected states differ visually. Terminal states, disconnection, and reduced-motion settings stop Canvas animation. External silence means waiting; it does not prove that the agent process is alive.
6. **Factory preview alignment.** Rejected counts sit inside their bin with 8px clearance from the reserved slots and bottom, and remain clear of travelling cards. The reader, builder, and oracle share a 10px logical gap above the belt. Square factory ink has balanced top/bottom margins; progress room labels retain a 24px right inset. Browser checks use actual Canvas text metrics and visible pixels, allowing 1px for scaling. Landscape/fit layouts fill the width and reserve action/log space. The avatar uses shared SVG/Canvas geometry.
7. **Cross-platform REA discovery.** Windows Node/NVM/APPDATA layouts, Unix global npm paths, Homebrew, nvm, custom prefixes, project-local installation, and an explicit script override are supported without shell/npm subprocess discovery.
8. **Desktop runtime and lifecycle.** A Tauri 2 shell starts a packaged Node.js backend on an ephemeral loopback port. Native target file/folder selection and JSON save commands are wired into the dashboard; browser fallback remains available. Backend tests verify API/SSE, model cancellation, MCP child shutdown, port release, stdin EOF, parent disappearance, and staged resource discovery. HTTP closes immediately while MCP cleanup completes; repeated shutdown requests share the same work. The backend has a five-second deadline and the native shell allows six seconds before forced termination. Desktop-only IPC policy and bundled `node` command resolution preserve ordinary web-mode behavior.
9. **Integrated desktop titlebar.** The frameless window shares the dashboard theme and offers Windows or macOS button arrangements. Native minimize, maximize/restore, close, titlebar dragging, and double-click behavior are connected through Tauri's window API. Maximize state updates the controls and frame styling. The host platform supplies the initial arrangement; the appearance preference alone is saved in the native app configuration directory. Browser tests verify native preference precedence over stale local storage, setter routing, reload, and protection against a late initial read overwriting a newer user selection. Browser mode hides native controls.
10. **Dedicated Settings and consistent menus.** The workspace Settings button and desktop titlebar gear open a dedicated page. Appearance uses explicit Windows/macOS choice cards with immediate, persistent updates; no native dropdown is needed to change the button arrangement. Connections links to the model, MCP, and external-agent dialogs. The gear remains available during demo playback, and returning restores playback. Reusable dark combobox/listbox menus replace native popups throughout the workspace, retain native form/change behavior, and support mouse, keyboard, typeahead, dynamic options, disabled states, validation, and modal top-layer interaction.
11. **Window-filling desktop demos and floating playback.** Desktop demos adapt to the client area without aspect-ratio letterboxing; export dimensions remain independent. Playback controls float above the preview and can be hidden or restored with a visible Playback controls button or H. The existing pause, seek, replay, speed, loop, and fullscreen controls remain available.
12. **Offline in-app video export.** The video dialog exports square 1080×1080, landscape 1920×1080, or portrait 1080×1920 at 30 fps. An isolated local preview captures the complete DOM and Canvas scene at explicit timestamps without an event stream or live model/tool calls. It preserves the current workspace, reports progress, and supports cancellation. Encoding tries H.264/MP4, then VP9/VP8 WebM according to browser capabilities. Desktop uses a native video save dialog; browser mode downloads the file. Local capture/encoding assets total roughly 437 kB of JavaScript with six license files, requiring no installed Chrome or FFmpeg for this path. The separate command-line recorder retains those dependencies.

The proxy queue is limited to 512 events / 4 MiB, with room reserved for completion notices. Overflow reports losses; shutdown waits at most six seconds. Queue state and acknowledgement IDs are not persisted. Each run retains 4096 acknowledgement IDs. Recovery after permanent disconnection, restart, or capacity overflow is not guaranteed; missing telemetry cannot be used to infer actual lost calls.

## Remaining work

1. **Real model and user-target acceptance.** No real model API is configured, common local model ports were unavailable, and no user-selected software path was supplied. Controlled DLL checks do not replace model or target acceptance. Native decompiler integration remains unverified.
2. **Persistent history and configuration.** Restart clears in-memory tasks and settings. Export exists; history import and paginated history do not. Deduplication indexes grow with calls and are released when sessions are evicted.
3. **Continuation and context budgets.** New tasks do not inherit a prior conversation. Runs are limited to 12 rounds. Large results need on-demand reading and configurable budgets.
4. **Streaming performance and agent heartbeats.** SSE disconnection is explicit and views are cached by content. Streaming model text still replaces complete blocks; very long responses would benefit from incremental rendering. External agent activity lacks heartbeat semantics.
5. **Specialized analysis views.** Summaries, paginated tables, basic Markdown, and code highlighting exist. Call graphs, control-flow graphs, evidence relationship graphs, argument forms, and task comparison do not.
6. **Distribution acceptance.** The 0.3.0 Windows installer payload, Settings, previews, dark menus and native video save passed real WebView2 acceptance. The installer wizard/uninstall flow and matching macOS/Linux builds still require host-level acceptance. REA and analysis engines remain external dependencies; packaging the dashboard does not validate native decompiler capabilities.

See [VALIDATION.md](VALIDATION.md) for evidence and scope. Test logs and real-tool reports are under `artifacts`.
