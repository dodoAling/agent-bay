Run tasks with a model API

Use a cloud or local endpoint with tool calling.

  1. Choose the API protocol.

    Select Chat Completions compatible or Anthropic Messages.

  2. Enter the connection details.

    Fill in the API base URL, the provider's exact Model ID, and an API key when required. Model IDs are entered manually.

  3. Connect and enable tools.

    Open Connect → Tools, connect REA or another MCP server, and select the tools the model may use.

  4. Start a task.

    Return to the workspace, describe the task, optionally choose a target, and click Start task. Agent Bay runs up to 12 model rounds.

Local model

For Ollama, use http://127.0.0.1:11434/v1 and an installed model that supports tool calling. Leave the API key empty when authentication is not required.

Configuration is checked when a task starts and is cleared when the local runtime restarts. Responses-only and other native API formats need a protocol adapter.

Analyze without a model

Run real tools with arguments you choose.

  1. Connect the tool server.

    Open Connect → Tools → Connect REA. Use Add another MCP server for a custom stdio command or Streamable HTTP endpoint.

  2. Check the connection.

    Expand Call a tool without a model. Select binary_session, enter {}, and click Run tool. This queries status; it does not load or analyze a target.

  3. Choose an analysis tool.

    Read its description, provide the target and parameters it requires, then run it. Arguments depend on the tool; use its schema rather than guessing.

  4. Inspect the result.

    The workspace shows the actual output, duration, and success or failure. Manual mode does not plan the next tool call.

Analysis engine required

Native decompilation requires an installed engine such as Hopper, Ghidra, or IDA. Listing REA tools alone does not confirm that an engine is ready. Run rea doctor to check the environment.

Connect Codex through MCP

Codex → local proxy → REA → this workspace

  1. Keep Agent Bay open.

    The generated configuration uses this runtime's address and detected local REA installation.

  2. Add the MCP configuration.

    Copy the block below into ~/.codex/config.toml, alongside your existing settings. Copy config inserts the current bridge token.

  3. Restart Codex and verify.

    Use /mcp to check the server, then ask Codex: Use agent_bay_rea to call binary_session with {}.
